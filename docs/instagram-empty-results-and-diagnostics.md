# Instagram 빈 검색 결과 및 진단 개선

## 배경

Windows 클라이언트의 `v2.3.4` 로그에서 특정 희소 키워드 두 개가 반복적으로 60초 timeout 처리됐다. 페이지 이동은 완료됐지만 게시물 링크와 영문 `No results found` 문구가 모두 나타나지 않았다. 같은 작업의 다른 키워드는 즉시 정상 처리되어 로그인이나 전체 네트워크 장애는 아니었다.

Instagram 검색 결과는 계정, 지역 및 서버 상태에 따라 달라질 수 있다. 빈 결과 화면에 특정 언어의 안내 문구가 항상 존재한다고 가정할 수 없으므로 표시 문자열에 의존한 판정이 직접 원인이었다.

## 빈 결과 처리

- 게시물 링크를 최대 15초 기다린다.
- 감지되지 않으면 검색 페이지를 한 번 새로고침하고 다시 확인한다.
- 재시도 후에도 게시물이 0개이면 오류가 아닌 정상 `미포함`으로 반환한다.
- 로그인, challenge/checkpoint, 검색 제한 및 Instagram 오류 화면만 명시적인 오류로 구분한다.
- `모든 게시물 스크린샷` 옵션이 켜져 있으면 0개 결과도 `1460 x 835` 규격으로 저장한다.
- 옵션이 꺼져 있으면 0개 결과의 스크린샷은 생성하지 않는다.

## Chrome 실행 경로

Windows 기본 설치 경로의 Google Chrome을 PATH보다 먼저 확인한다. PyInstaller에 포함된 Playwright Chromium 경로는 시스템 Chrome으로 인정하지 않는다. Chrome이 없으면 설치 안내 오류를 표시한다.

## 진단 로그

로그 파일은 `Downloads/viral-reporter/debug.log`에 JSON Lines 형식으로 저장된다. 10MB 단위로 회전하며 7일간 보관한다.

애플리케이션 시작 시 다음 정보를 기록한다.

- 애플리케이션 버전과 패키징 여부
- Python, 운영체제 및 화면 정보
- 실제 선택된 Chrome 실행 경로와 버전

Instagram 검색 시 다음 정보를 기록한다.

- job/task ID, 키워드와 검색 옵션
- 각 시도의 응답 상태, 최종 URL과 제목
- 게시물 수, DOM 준비 상태와 브라우저 언어
- 제한된 본문 미리보기 및 오류 유형별 누적 횟수
- 재시도 및 빈 결과 판정
- 스크린샷 경로, 크기와 파일 크기

내부 API 진단을 위해 `document`, `xhr`, `fetch`, `script` 요청의 HTTP 4xx/5xx와 네트워크 실패, 콘솔 오류 및 JavaScript 오류를 기록한다. URL 쿼리, fragment, 쿠키, 인증 헤더, 요청·응답 본문은 기록하지 않으며 메시지는 500자로 제한한다. 이미지와 영상 요청은 로그 과다 방지를 위해 제외한다.

페이지 상태 오류에는 별도 진단 스크린샷을 저장한다. 전체 HTML은 로그 크기와 민감정보 문제로 기록하지 않는다.

## 사용자 접근

메인 화면의 `데이터·로그 폴더 열기` 버튼이 결과와 `debug.log`가 함께 있는 폴더를 연다. 별도 로그 버튼은 같은 폴더를 중복해서 열기 때문에 두지 않는다.

## 검증

- 제공된 15개 키워드 실제 검색: 모두 예외 없이 완료
- `블루드래곤팟타이누들키트`: 게시물 3개, 대상 릴스 2개 매칭
- `코스트코팟타이레시피`: 게시물 3개, 대상 릴스 2개 매칭
- 희귀 무작위 키워드 4개: Instagram 추천 결과 2~10개, 정상 `미포함`
- 게시물 0개 및 안내 문구 없음: 재시도 후 정상 `미포함` 단위 테스트
- 빈 결과 전체 스크린샷 옵션: 고정 크기 파일 생성 단위 테스트
- 관련 인프라 테스트 23개 통과
